1 and 2. Export: three scopes, one click each

Add an options argument to the existing plugin methods rather than new methods, so the Tampermonkey menu items keep working unchanged:

exportJSON(opts?: { scope?: "page" | "site" | "all"; includeArchived?: boolean }): Promise<ExportDocument>
exportMarkdown(opts?: same): Promise<string>

// scope: "page" -> pageId === current page
//        "site" -> host of page.normalizedUrl matches the current host
//        "all"  -> every stored page (today's behaviour, stays the default)

Filtering happens on the already-collected PageGroup[], so no storage change and no migration. Filenames carry the scope: webmods-annotations-app.notion.com-2026-08-17.md.

3. Archived notes

State

metadata.archived = Date.now() through the existing updateNote(id, { metadata }). No schema bump, no migration, and older builds simply ignore the key.

New annotator API: archiveNote(id) and unarchiveNote(id), plus commands entries so the widget and the menu can reach them.

Behaviour

  • Archived notes get no page marker and no highlight. That is the point of archiving.
  • They drop out of the Notes count and sit behind Archived (n), each with Restore.
  • Anchor resolution is skipped for them, so a stale archived note never wakes the mutation observer.
  • Exports keep them with the flag intact, so a backup and restore cycle never silently drops or resurrects notes.

4. Corner widget

Sharestar...
Edit mode
Annotate mode, click a block to add a note (Esc to exit)

The panel sits 44px below the corner so it never covers the site's own top-right controls (Notion's Share and star, GitHub's avatar menu, Gmail's settings).

Mechanics

  • A 22x22 hotspot at the corner with pointer-events: none. Detection rides the pointermove listener the annotator already has, so nothing new intercepts clicks.
  • Shows after a 250 ms dwell inside the corner, hides 400 ms after the pointer leaves both hotspot and panel.
  • The toggle mirrors annotate mode both ways: Alt+Shift+A flips the switch, and the switch drives setMode. The button calls the existing sidebar.toggle command.
  • Lives in the same shadow-root layer (UI_ATTR), so it is never itself annotatable.
  • Option ui.cornerWidget: false turns it off. On by default in the userscript host.
the risk I would push back on

Top-right is the most crowded corner on the web, and this script runs on *://*/*. Even with pointer-events: none on the hotspot, the panel is clickable while shown, so a stray hover parks a 196px card over whatever the site keeps up there until you move away. The 44px offset and the dwell delay make that survivable, not invisible. If it annoys you, the honest fix is bottom-right, which almost no app uses for primary controls.

Failure modes I will cover

No-hover devices

A touch device never fires the corner hover. The shortcuts and the TM menu stay the guaranteed entry points, so the widget is additive and never the only path.

Fullscreen video and games

The panel would float over a fullscreen element, so it hides whenever document.fullscreenElement is set.

Export of a huge store

collectPages already loads everything into memory and scoping filters after that. For a large store the site scope is the cheap path, all stays as slow as today.

Open questions

Q1. "All the notes of a website" means

Your words could mean the current page or the whole domain. The sidebar already lists the current page, which is why I lean host-wide.

Q2. One click means one format per button

A dropdown would cost a second click. So either two small buttons per scope, or one format on the button with the other left in the TM menu.

Q3. Widget corner

You asked for top-right. That is where nearly every app puts its own controls, and this script matches every site.

Q4. Archived notes in exports

JSON has to keep them or a backup and restore cycle deletes work. Markdown is for reading, so that one is a real choice.

Q5. Ship order

Four features, one commit each, each verified live on Notion before the next.
